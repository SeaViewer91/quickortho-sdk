# 핵심 개념

## 1. 워크스페이스

SDK는 **영상 폴더 하나 = 워크스페이스 폴더 하나** 단위로 처리함. 워크스페이스는 처리 결과와 중간 데이터를 모두 담는 폴더이며,
`quickortho.Project` 객체 하나가 워크스페이스 하나를 다룸.

```text
<workspace>/
├── orthomosaic.tif        정사 모자이크 (Cloud Optimized GeoTIFF. RGB는 RGBA, 다중분광은 밴드별 float32 반사율)
├── dsm.tif                정사투영에 쓴 간이 DSM (float32)
├── preview.png            긴 변 2048px 미리보기 (RGBA)
├── indices/               (다중분광) 고른 식생·수분 지수 (0.4.1부터. 0.4.0은 indices.tif·ndvi.png)
│   ├── NDVI.tif           지수마다 float32 단일 밴드 COG, nodata NaN
│   └── NDVI.png           색 띠 미리보기 (긴 변 최대 2048px)
├── report.json            처리 보고서
├── preview/               빠른 미리보기 결과 (Project.preview() 실행 시)
└── project/               정렬 결과·보정 데이터 (SDK가 관리함. 직접 수정하지 않음)
    ├── meta.json          영상 폴더 경로, 영상별 GPS, SDK 버전, 마지막 정사 모자이크 옵션 (다중분광은 원본 밴드 폴더)
    ├── msref/             (다중분광) SfM에 쓴 기준 밴드 8비트 영상 (<원래 이름>.jpg)
    ├── water/             영상별 수면 판별 결과 <영상 경로>.png (0 육지, 100 수면 후보, 200 확실한 수면)
    ├── water.json         수면 판별 요약 (출처 auto·user, 수면 비율)
    ├── base/              정렬 직후 재구성 (COLMAP 형식, 지역 좌표계)
    ├── base_frame.json    base 좌표계 {"epsg", "origin"}
    ├── align_report.json  정렬 단계 보고서
    ├── edits.json         보정 수정 사항 (GCP, 타이포인트, 삭제한 점, 자동 제거 기준)
    ├── refined/           마지막 보정 결과 재구성 (보정한 경우)
    ├── refined_frame.json
    ├── refined_extra.json
    ├── refine_report.json 마지막 보정 보고서
    └── cache/             사진 조각 이미지 (predict(chips=True))
```

### 워크스페이스 상태

| 상태 | 조건 | 확인 방법 |
|---|---|---|
| `new` | 아직 정렬하지 않음 | `not project.is_aligned` |
| `aligned` | 정렬 결과(`project/base`)가 있음 | `project.is_aligned` |
| `rendered` | 정사 모자이크가 있음 | `project.is_rendered` |
| `refined` | 정밀 보정 결과가 있음 | `project.is_refined` |

`print(project)`로 현재 상태를 볼 수 있음: `Project(workspace='...', state='rendered')`.

### 무엇이 언제 지워지는가

| 작업 | 지워지는 것 | 유지되는 것 |
|---|---|---|
| `align()` / `process()` | 이전 정렬·보정 결과, 정사 모자이크·DSM·미리보기 PNG·`report.json`, 사진 조각 캐시, 삭제한 점 목록, 마지막 정사 모자이크 옵션, 자동 수면 판별 결과(새로 판별한 것으로 교체) | GCP·수동 타이포인트의 사진 표시, 자동 제거 기준, `preview/`, 사용자 수면 마스크(`set_water_masks`) |
| `orthomosaic()` | 이전 정사 모자이크·DSM·미리보기 PNG (새 결과로 교체). 다중분광은 `indices/`와 0.4.0 형식 `indices.tif`·`ndvi.png`도 새 선택으로 교체 | 정렬·보정 결과 |
| `make_indices()` (다중분광) | `indices/`의 이전 지수 파일, 0.4.0 형식 `indices.tif`·`ndvi.png` (새 선택으로 교체) | 정사 모자이크·DSM·미리보기 PNG, 정렬·보정 결과 |
| `refine()` | 이전 보정 결과 | 정렬 결과, 수정 사항 |
| `reset_refinement()` | 보정 결과 | 정렬 결과, 수정 사항 |

삭제한 점 목록은 재구성의 3D 점 ID를 가리키므로, 정렬을 새로 하면 의미가 없어져 비움.
GCP·타이포인트의 사진 표시는 사진 화소 좌표라서 정렬과 무관하게 유지함.

### 결과물 교체 방식

정사 모자이크와 DSM은 임시 파일(`*.tmp.tif`)에 먼저 쓰고, 모두 끝나면 기존 파일과 바꿈.
따라서 `orthomosaic()`·`refine()` 도중 중단·실패해도 **이전 결과물은 그대로 남고** 임시 파일은 지워짐.
다만 `process()`(와 `align()`)는 정렬 단계에서 이전 결과물을 먼저 지우므로, 중단하면 정사 모자이크가 없는 상태가 됨.

### 동시 처리

- 같은 워크스페이스를 여러 스레드·프로세스에서 동시에 처리하면 안 됨 (결과가 섞임)
- 서로 다른 워크스페이스는 별도 **프로세스**로 동시에 처리할 수 있음. 다만 SfM은 기본으로 모든 코어를 쓰므로
  동시에 여러 작업을 돌리면 각 작업이 느려지고 메모리도 합산됨. 서버에서는 동시 작업 수를 제한하는 것을 권장함
- 한 프로세스 안에서 여러 스레드로 서로 다른 워크스페이스를 처리하는 것은 권장하지 않음
  (COLMAP 로그 설정 등 일부 전역 상태를 공유함)

### 영상 폴더 경로

워크스페이스는 원본 영상 폴더의 **절대 경로**를 `project/meta.json`에 기록하고, 정사 모자이크를 만들 때 원본 영상을 다시 읽음.
정렬 후 영상 폴더를 옮기거나 지우면 `orthomosaic()`·`refine()`이 `InputError(code="image_dir_missing")`로 실패함.
영상 폴더를 옮겨야 한다면 정렬부터 다시 하는 것이 안전함.

## 2. 처리 단계

```text
scan → (preview) → water → features → matching → mapping → georef → dsm → color → ortho → finalize
└──────────────────────────── align() ──────────────────────────┘   └────── orthomosaic() ───────┘
└────────────────────────────────────────── process() ───────────────────────────────────────────┘
```

| 단계(`stage`) | 내용 |
|---|---|
| `scan` | 폴더의 JPG에서 EXIF·DJI XMP를 읽음. 헤더만 읽으므로 빠름 |
| `footprints`, `quicklook` | (미리보기 전용) 촬영 범위 계산, 간이 모자이크 |
| `water` | 영상별 수면 판별 ([11절](#11-수면-처리)). `water="off"`·다중분광이면 없음. 정사 단계에서 저장된 판별 결과가 없을 때도 나옴 |
| `features` | SIFT 특징점 추출 (pycolmap). 영상 긴 변을 `max_image_size`(기본 2000px)로 줄이고 업샘플 없이 추출함. 수면 처리를 켜면 넓은 수면 안쪽은 빼고 추출함 |
| `matching` | 영상이 `exhaustive_below`(기본 40장) 이하면 전수 매칭, 그보다 많으면 GPS가 가까운 `num_neighbors`(기본 15장)와만 매칭함 |
| `mapping` | 전역 SfM(GLOMAP 방식)을 먼저 시도하고, 정합률이 `min_registered_ratio`(기본 80%) 미만이면 증분 SfM으로 다시 시도해 더 많이 정합된 쪽을 씀 |
| `georef` | 카메라 중심과 GPS 위치(UTM)의 닮음변환(회전·축척·이동)을 RANSAC(허용 오차 10m)으로 구해 적용함 |
| `dsm` | 희소 점군에서 재투영 오차 2px 초과·관측 3장 미만 점과 높이 이상치를 빼고 격자로 보간함. 점군 밖은 가우시안 정규화 합성곱으로 부드럽게 외삽함. 수면 처리를 켜면 확정한 수면 칸을 물가 높이의 평면으로 덮음 |
| `bands` | (다중분광) 밴드 정합 미세 조정, 캡처 간 반사율 보정 ([10절](#10-다중분광-처리)) |
| `color` | 영상 간 밝기·색 보정. 영상마다 완만한 이득 곡면을 구함 ([밝기·색 보정](#밝기색-보정)). `color_balance=False`이거나 영상이 1장이면 건너뜀 |
| `ortho` | 출력 512px 타일마다 DSM에 역투영하고, 화소마다 영상 중심에 가장 가까운 영상 하나로 칠함. 영상 경계 몇 화소만 섞음 ([심라인 합성](#8-정사-모자이크-합성-심라인)). 타일은 4×4 묶음 순서로 처리해 같은 영상을 연달아 씀 |
| `finalize` | 오버뷰 생성, COG 변환, 미리보기 PNG 생성 |
| `refine` | (보정 전용) 수정 사항 적용, 번들 조정 |

## 3. 입력 영상 조건

- **형식**: JPG(`.jpg`, `.jpeg`). 다중분광 카메라(MicaSense RedEdge·Altum 계열)의 밴드 TIFF도 읽음 ([10절](#10-다중분광-처리)).
  하위 폴더는 기본으로 읽지 않음 (`scan(recursive=True)`는 스캔만 지원)
- **GPS**: 처리 대상 영상 중 GPS가 있는 영상이 **3장 이상** 있어야 함. GPS가 없는 영상도 SfM에는 쓰지만 좌표 정렬에는 쓰지 않음
- **최소 장수**: 처리 대상 영상 3장 이상. 실제로는 중복도가 충분한 10장 이상을 권장함
- **촬영 자세**: 연직 촬영을 전제로 함. 짐벌 pitch가 -70°보다 큰(덜 숙인) 영상은 경사 촬영으로 표시하고 경고함. 처리에서 빼지는 않음
- **롤링 셔터**: Mavic 2 Pro(`L1D-20c`), Mavic 2 Zoom(`FC2204`)은 롤링 셔터 카메라로 경고함. 보정은 하지 않으므로 저속 비행·정지 촬영을 권장함

### 카메라 자동 선별

Mavic 3E·Matrice 4E처럼 한 기체에 카메라가 여럿이면 광각·망원 영상이 한 폴더에 섞일 수 있음.
SDK는 같은 기종(제조사+모델) 안에 카메라(초점거리·해상도 조합)가 여럿이면 **광각 카메라 하나만** 처리 대상으로 남김.

1. 파일명 접미사가 `_W`인 카메라 (DJI 광각 영상 규칙, 예: `DJI_0001_W.JPG`)
2. 없으면 35mm 환산 초점거리(없으면 실제 초점거리)가 가장 짧은 카메라

기종이 다른 영상이 섞인 폴더는 모두 처리 대상으로 둠. 같은 카메라끼리는 내부표정(초점거리·왜곡)을 공유해 추정함.
제외한 카메라와 사유는 `ScanResult.excluded_cameras`로 확인함.

### 고도 정보

- 좌표 정렬에는 EXIF GPS 고도 또는 DJI XMP `AbsoluteAltitude`(있으면 우선)를 씀. 둘 다 없으면 XMP `RelativeAltitude`를 씀
- 미리보기는 XMP `RelativeAltitude`(이륙 지점 기준 고도)를 쓰며, 지면을 이륙 지점 높이의 평면으로 가정함
- 기종마다 절대 고도의 기준(타원체고·해발고)이 다를 수 있음. GCP 없이 만든 DSM의 **절대 높이 값은 참고용**임

## 4. 좌표계

- **결과 좌표계**: 기본으로 촬영 위치(GPS 중앙값)가 속한 **WGS84 UTM 구역**으로 자동 결정함
  (예: 한국 동부 EPSG:32652, 서부 EPSG:32651). `OrthoOptions(epsg=5186)`처럼 투영 좌표계를 지정할 수 있음.
  좌표계는 정렬 단계에서 정해지므로, 바꾸려면 다시 정렬해야 함
- **GCP 보정 후**: GCP의 좌표계(예: EPSG:5186 GRS80 중부원점)로 결과를 만듦. GCP 좌표계가 경위도(EPSG:4326 등)이거나
  여러 좌표계가 섞여 있으면 정렬 좌표계(`epsg`를 줬으면 그 좌표계, 아니면 UTM)를 유지함
- **지역 좌표계**: `project/` 안의 재구성은 수치 안정성을 위해 `투영 좌표 - origin`으로 저장함. `origin`은 `*_frame.json`에 있음
- 미리보기(`preview.geojson`, `corners_lonlat`)와 보고서의 `preview_corners_lonlat`은 WGS84 경위도(경도, 위도 순)임

## 5. 정확도

| 구분 | 의미 | 결정 요인 |
|---|---|---|
| 상대 정합 | 모자이크 안에서 영상끼리 얼마나 잘 맞는가 | SfM (재투영 오차, `sfm.mean_reprojection_error_px`) |
| 절대 위치 | 모자이크가 지도상 실제 위치에 얼마나 맞는가 | GPS 정확도 (RTK가 아니면 수 m) 또는 GCP |
| 높이 | DSM 값과 정사투영 기하 | 희소 점군 밀도, GPS 고도 기준 |

- `georef.gps_residual_rms_m`은 정렬 후 카메라 위치와 GPS 위치의 수평 차이임. GPS 자체의 오차가 일정하게 치우쳐 있으면
  (예: 모든 영상이 3m 동쪽으로 치우침) 잔차는 작아도 절대 위치는 그만큼 어긋나 있음. 절대 위치는 검사점으로만 판단할 수 있음
- 재투영 오차는 보통 0.5~1.5px임. 2px를 넘으면 초점 흐림·롤링 셔터·움직이는 물체(파도, 차량)를 의심함
- 간이 DSM은 점군 간격(수 m) 수준이라 건물·수목 경계에서 겹침·늘어짐이 생길 수 있음

## 6. GSD(지상 표본 거리)와 출력 격자

- **원본 GSD**: 정합된 영상마다 `(카메라 높이 - 지면 높이 중앙값) / 초점거리(px)`를 구한 중앙값
- **출력 GSD**: `OrthoOptions.gsd_m`을 주면 그 값, 아니면 `원본 GSD × gsd_scale`(기본 1, 0.2.x까지는 2)
- `gsd_scale=1`은 원본 해상도, `2`는 가로세로 절반(화소 수 1/4)임. 해상도를 높이면 처리 시간·파일 크기가 대략 화소 수에 비례해 늘어남
- **출력 범위**: 기본은 정합 영상 촬영 범위 전체. `OrthoOptions.bounds`로 범위를 정할 수 있음 (범위 밖은 알파 0)
- **격자 맞춤**: 결과 경계는 항상 `grid_origin`(기본 (0, 0))에서 GSD 배수인 위치로 바깥쪽으로 맞춤.
  그래서 좌표계·`gsd_m`·`grid_origin`이 같으면 여러 결과의 화소 경계가 정확히 겹치고, `bounds`까지 같으면 배열 크기도 같음

## 7. 정사투영에 쓰는 지형면 (DSM)

| `OrthoOptions.dsm` | 방식 | 쓰는 곳 |
|---|---|---|
| `"sparse"` (기본) | SfM 희소 점군을 격자로 보간 | 일반 지형 |
| `"plane"` | 높이 `dsm_z`의 수평면 (없으면 희소 점군 높이 중앙값) | 수면 위주 영상, 평탄지. 점군이 흔들려 정사영상이 번질 때. 바다·호수가 일부만 찍혔으면 `"sparse"`와 수면 처리([11절](#11-수면-처리))가 나음 |
| 파일 경로 | 외부 DSM/DEM GeoTIFF를 결과 격자로 재투영 | 국토지리정보원 DEM, LiDAR 결과 등 더 정확한 지형이 있을 때 |

- 외부 DSM은 좌표계가 달라도 됨 (자동 재투영). 결과 범위 중 외부 자료가 없는 곳은 부드럽게 외삽함
- 외부 DEM은 보통 해발고이고, GCP 보정 전 재구성 높이는 GPS 고도 기준이라 수십 m 차이가 날 수 있음.
  `dsm_vertical_align=True`(기본)면 희소 점군과의 높이 차이 중앙값만큼 외부 DSM을 옮겨 맞춤. 적용한 값은 `report.json`의 `dsm.vertical_offset_m`
- `"plane"`의 `dsm_z`는 결과 좌표계의 높이 기준임. GCP 보정 전에는 GPS 고도 기준이므로 해수면 0m가 재구성에서 0이 아닐 수 있음.
  이때는 `dsm_z=None`(점군 중앙값)으로 시작해 결과를 보고 조정함

- `"sparse"`의 격자 간격은 평균 점 간격의 0.5배(최소 0.5m)이고, 중앙값 필터(3×3)와 약한 가우시안(σ 0.5격자)으로 잡음만 누름.
  0.2.x는 1.5배 격자에 평활화가 강해 갈대·관목·작은 기복의 높이가 지워졌고, 그만큼 영상 간 투영 위치가 어긋났음

## 8. 정사 모자이크 합성 (심라인)

한 지점은 보통 여러 영상에 찍혀 있음. 0.3.0부터는 이 영상들을 평균하지 않고 **화소마다 영상 하나를 골라** 칠함.

- 고르는 기준: 그 지점을 영상에 투영한 위치가 영상 중심에 가장 가까운 영상. 중심에 가까울수록 연직에 가깝고 렌즈 왜곡·기울어짐이 작음
- 영상이 바뀌는 경계선 양쪽 몇 화소(출력 기준 약 6화소)만 섞어 밝기 차이로 생기는 이음매를 감춤
- 화소마다 같은 규칙으로 정하므로 타일 크기·처리 순서·`grid_origin`이 달라도 이음매가 같은 자리에 생김

평균하면 DSM 높이가 실제와 다른 곳(수면, 갈대, 부표·통 같은 작은 물체, 건물 지붕)에서 영상마다 투영 위치가 조금씩 달라
물체가 여러 개로 흐리게 겹쳐 보였음(고스팅). 영상 하나를 고르면 이 어긋남은 경계선의 작은 단차로만 남음.
대신 경계선이 높이가 불확실한 물체를 지나가면 물체가 약간 끊겨 보일 수 있음. 겹쳐 흐려지는 것보다 판독에 유리함.
`report.json`의 `ortho.blend`가 `"seamline"`이면 이 방식으로 만든 결과임.

### 밝기·색 보정

영상 하나를 골라 붙이면, 영상끼리 노출이나 태양 방향에 따른 지면 반사(모래사장, 잔디밭)가 다를 때 경계를 따라
계단·다각형 모양의 밝기 단차가 선명하게 보임. 위치 어긋남이 아니라 넓은 범위의 밝기 차이이므로, 0.3.1부터 정사투영 전에
`color` 단계에서 영상마다 밝기 보정 곡면을 구해 읽은 색에 곱함 (다중 대역 블렌딩의 저주파 대역에 해당). 세부 질감은 고른 영상 그대로임.

1. 결과 범위를 거친 격자(셀 한 변은 원본 GSD의 16배 이상, 셀 수 200만 개 이하)로 나누고, 셀 중심을 DSM 높이로 각 영상에 투영함
2. 영상을 셀 크기 정도로 줄이고 흐리게 해 셀 위치의 저주파 색을 읽음
3. 셀마다 여러 영상의 밝기를 심라인 점수(영상 중심 거리)로 넓게 가중해 로그 공간에서 섞어 목표 밝기를 만듦
4. 영상마다 목표/자기 밝기 비(0.5~2배로 제한)를 영상 좌표의 2차 다항식(채널별)으로 맞춤. 이음매 근처 표본에 가중을 더 주고,
   반복 재가중(Tukey)으로 건물 옆면·파도처럼 영상마다 내용이 다른 곳은 이상값으로 뺌
5. 곡면을 영상 좌표 64×48 격자의 이득 맵으로 만들어 정사투영 때 곱함

- 영상 한 장만 덮는 곳은 목표가 자기 밝기와 같아 원래 밝기에 가깝게 유지됨. 이음매 양쪽은 같은 목표로 맞춰짐
- 이득 맵은 영상 좌표에 묶여 있으므로 타일 경계와 무관하게 결과가 이어짐. 외부·평면 DSM에서도 동작함
- 이득은 결과 범위(`bounds`)가 아니라 **촬영 범위 전체**로 구함. 그래서 범위·격자 기준점을 바꿔 만든 결과끼리도 같은 이득을 써서,
  나눠 만든 결과를 이어 붙여도 밝기가 어긋나지 않음 (좁은 `bounds`를 줘도 이 단계는 영상 전체를 읽음).
  다만 간이 DSM(`sparse`)은 결과 범위로 보간하므로 범위가 다르면 지형면이 조금 달라질 수 있음
- 곡면 없이 셀별 이득을 그대로 쓰면 잔디 단차는 더 깨끗해지지만 건물 옆면에 지붕색이 번지는 얼룩이 생겨 쓰지 않음
- 고층 건물 지붕선이 이음매에서 어긋나는 것은 밝기가 아니라 간이 DSM 높이 문제라 이 보정으로 바뀌지 않음
- 끄려면 `OrthoOptions(color_balance=False)`, 명령줄 `--no-color-balance`

## 9. 빠른 미리보기의 원리와 한계

미리보기는 SfM 없이 EXIF·XMP만 씀.

- 촬영 범위: 카메라 위치·상대고도·짐벌 yaw/pitch·화각으로 지면(이륙 지점 높이의 평면) 사각형을 구함
- 중복도: 격자마다 몇 장의 촬영 범위에 들어가는지 셈
- 누락 구역: 촬영 범위 안쪽 구멍과, 서로 떨어진 촬영 범위 사이의 좁은 틈(영상 한 장 폭 이하)을 누락으로 판정함.
  바깥쪽 계단 모양 오목부는 누락으로 보지 않음
- 간이 모자이크: 영상을 1/8로 축소 디코딩해 평면 가정 호모그래피로 배치함
- 짐벌 yaw가 기체 yaw와 일정하게 어긋난 경우(Mavic 2 샘플에서 약 31° 사례 확인)를 감지해 자동 보정함
- XMP가 없으면 진행 방향으로 yaw를 추정하고 35mm 환산 24mm 화각을 가정함 (경고 표시)

위치 오차가 수 m 수준이므로 **촬영 누락 확인용**이며, 측정에는 쓰지 않음.

## 10. 다중분광 처리

MicaSense RedEdge-MX·RedEdge-P·Altum·Altum-PT의 밴드 TIFF 폴더를 RGB 폴더와 같은 함수로 처리함
(`qo.process()`, `Project.create(...).process()`). 폴더에 다중분광 영상이 있으면 자동으로 이 경로를 탐.
결과 `orthomosaic.tif`는 밴드별 **반사율**(float32)이고, 고른 식생·수분 지수를 `indices/<이름>.tif`로 함께 만듦.

### 영상 인식

- 폴더의 TIFF 중 Pix4D 카메라 XMP(`Camera:BandName`, `Camera:RigCameraIndex`)가 있는 파일만 밴드 영상으로 봄
- `MicaSense:CaptureId`로 같은 순간에 찍은 밴드를 한 캡처로 묶음. 밴드가 빠진 캡처, GPS가 없는 캡처는 제외하고 경고함
- 패널 촬영(`Camera:CalibrationPicture=2`와 `Albedo`·`ReflectArea`가 있는 캡처)은 정렬에서 빼고 반사율 계산에만 씀
- 같은 폴더의 JPG는 쓰지 않음 (경고)
- 하위 폴더는 읽지 않음. MicaSense 카메라는 `SET/000/IMG_*.tif`처럼 저장하므로 `000` 폴더(또는 밴드 TIFF를 모은 폴더)를 지정함
- 명시한 `radiometry`에 필요한 자료(DLS·패널 촬영)가 없으면 정렬(SfM) 전에 `invalid_argument`로 알림

### 처리 순서

```text
scan → scan(기준 밴드 영상 준비) → features → matching → mapping → georef → dsm → bands → ortho → finalize
```

1. **기준 밴드**: 팬크로매틱이 있으면 그것, 없으면 560nm에 가장 가까운 밴드. 출력 밴드는 팬크로매틱·열적외를 뺀 밴드(파장 순)
2. **SfM 입력**: 기준 밴드를 흑색 수준·주변 감광·노출 보정 후 비행 전체 공통 배율로 늘이고(감마 0.5, CLAHE) 8비트 JPEG로 저장함
   (`project/msref/<원래 이름>.jpg`). 내부표정은 메타데이터(초점거리·주점 mm × 초점면 해상도, 왜곡 k1·k2·k3·p1·p2 → COLMAP
   FULL_OPENCV)를 쓰고 번들 조정에서 고정함. 정밀 보정(`refine()`)에서도 고정함
3. **방사보정** (제조사 공개 모델):
   L = V · R(y) · (p − p_BL) · a1 / (g · t_e · 2^N),  R(y) = 1 / (1 + a2·y/t_e − a3·y)
   - p: 원시 값, p_BL: 흑색 수준, g: 이득(ISO/100), t_e: 노출(초), N: 비트 수, V: 주변 감광 보정(방사형 또는 2차원 다항식의 역수)
   - 음수(잡음)는 자르지 않음 (어두운 물체의 평균이 치우치지 않게)
4. **반사율**: ρ = π·L / E. E는 입사광 센서(DLS)의 수평 입사광을 시간 순 5캡처 이동 중앙값으로 다듬은 값.
   DLS 단위 배율은 `IrradianceScaleToSIUnits`가 있으면 그 값, DLS2(`HorizontalIrradiance` 태그)는 0.01, 아니면 1.
   패널 촬영이 있으면 밴드별 배율 k = albedo / ρ_패널(DLS)를 곱함 (`OrthoOptions.radiometry`, 아래 표)
5. **밴드 카메라**: 기준 밴드 자세에 rig 회전(`Camera:RigRelatives`, Rx·Ry·Rz, 도)을 더한 카메라로 밴드마다 DSM에 직접 투영함.
   밴드를 영상 평면에서 겹치지 않으므로 저고도·높은 물체의 시차도 DSM 정확도만큼 맞음.
   `RigTranslations`(렌즈 위치 차)는 시험 비행(고도 21m)에서 적용하면 3~4화소 어긋나 기본으로 쓰지 않음
6. **rig 미세 조정** (`bands` 단계): 캡처 10개에서 기준 밴드 영상을 현재 모델(rig + DSM)로 각 밴드 영상 좌표에 옮기고,
   로그 경사도 크기를 ECC로 맞춰 남은 이동량을 잼. 중앙값을 밴드 카메라의 작은 회전으로 바꿔 적용하고 한 번 더 반복함.
   마지막으로 4캡처에서 잔차만 재서 보고함 (`multispectral.radiometry.band_alignment`)
7. **방사 블록 조정** (`OrthoOptions.ms_normalize`, 기본 켬): SfM 타이포인트(최대 2만 개)에서 캡처별 밴드 반사율(로그)을 읽고,
   점 평균과의 차이를 캡처·밴드 이득으로 설명함. Tukey 반복 재가중으로 이상값(건물 옆면, 움직이는 물체)을 빼고,
   관측이 적은 캡처는 이득 1 쪽으로 당김. 캡처 이득의 평균은 1로 고정해 DLS·패널로 정한 **전체 반사율 수준은 바꾸지 않음**.
   구름·DLS 기울기로 생기는 캡처 경계 단차를 줄임
8. **정사투영**: 심라인은 기준 밴드 카메라로 화소마다 한 번만 고르고, 모든 밴드를 그 영상에서 각자 카메라로 읽음
   (지수가 서로 다른 촬영의 값으로 계산되지 않게). 모든 밴드가 있는 화소만 유효하고 나머지는 NaN.
   출력 GSD는 출력 밴드의 원본 GSD × `gsd_scale`. 밝기·색 보정(`color`)은 하지 않음 (반사율을 바꾸지 않기 위해)
9. **산출물**: `orthomosaic.tif`(반사율 float32 COG, 밴드 설명에 밴드 이름),
   `preview.png`(반사율 R·G·B, Blue가 없으면 NIR·Red·Green 위색, 1~99백분위 늘이기),
   `indices/<이름>.tif`·`.png`(고른 지수마다, 아래 "식생·수분 지수" 참고)

### 반사율 환산 방식 (`OrthoOptions.radiometry`)

| 값 | 방식 | 쓰는 경우 |
|---|---|---|
| `"auto"` (기본) | DLS와 패널이 모두 있으면 `dls+panel`, DLS만 있으면 `dls`, 패널만 있으면 `panel`, 둘 다 없으면 `radiance` | 보통 |
| `"dls+panel"` | DLS로 캡처마다 입사광 변화를 따라가고, 패널로 밴드별 수준을 맞춤 | 권장 (MicaSense 예제 데이터에서 DLS만 쓰면 패널 반사율이 실제의 0.64~2.2배) |
| `"dls"` | ρ = π·L/E | 패널 촬영이 없을 때 |
| `"panel"` | ρ = L · albedo / L_패널 | DLS가 없을 때. 비행 중 조도 변화는 반영하지 못함 |
| `"radiance"` | 반사율로 바꾸지 않고 방사휘도(W/m²/sr/nm) | 자체 보정을 할 때. 블록 조정도 하지 않음 |

- 패널 방식은 **모든 출력 밴드에 패널 정보가 있어야** 씀. 패널 촬영이 있어도 카메라가 일부 밴드에서 패널을 찾지 못하면
  (예: MicaSense Altum 공개 예제의 Green) `auto`는 DLS가 있으면 `dls`, 없으면 `radiance`가 되고 보고서에 경고를 남김
  (`radiometry.panel_missing_bands`). 방식을 직접 지정한 경우에는 경고하지 않음
- 요청한 방식에 필요한 자료(DLS·패널)가 없으면 `InputError`(`invalid_argument`)

### 식생·수분 지수 (`OrthoOptions.indices`)

반사율 정사 모자이크에서 고른 지수만 계산함 (0.4.1부터). 기본값 `None`은 NDVI·NDRE·GNDVI(0.4.0과 같은 결과), `[]`는 만들지 않음.
이름은 대소문자를 가리지 않고, 중복은 하나로, 순서는 아래 표 순서로 정리함. 모르는 이름은 처리 시작 전에 `InputError`(`invalid_argument`).

| 이름 | 식 | 필요한 밴드 | 미리보기 범위 | 쓰는 곳 |
|---|---|---|---|---|
| NDVI | (NIR − Red) / (NIR + Red) | NIR, Red | −0.2 ~ 0.9 | 정규식생지수. 식생 활력 일반 |
| NDRE | (NIR − RE) / (NIR + RE) | NIR, Red edge | −0.1 ~ 0.6 | 생육 후기·질소 상태 (NDVI가 포화되는 밀식 작물) |
| GNDVI | (NIR − G) / (NIR + G) | NIR, Green | −0.2 ~ 0.9 | 엽록소 함량 |
| NDWI | (G − NIR) / (G + NIR) | Green, NIR | −0.6 ~ 0.6 | 수면 구분 (McFeeters). 물이 양수. 파랑 색 띠 |
| OSAVI | (NIR − Red) / (NIR + Red + 0.16) | NIR, Red | −0.2 ~ 0.8 | 식생이 성긴 곳 (토양 영향 보정) |
| SAVI | 1.5 (NIR − Red) / (NIR + Red + 0.5) | NIR, Red | −0.2 ~ 0.8 | 토양 보정 (L = 0.5) |
| EVI | 2.5 (NIR − Red) / (NIR + 6 Red − 7.5 Blue + 1) | NIR, Red, Blue | −0.2 ~ 0.9 | 식생이 빽빽한 곳 (대기·배경 보정) |
| CIre | NIR / RE − 1 | NIR, Red edge | 0 ~ 4 | 적색경계 엽록소지수 |
| CIg | NIR / G − 1 | NIR, Green | 0 ~ 8 | 녹색 엽록소지수 |

- 밴드는 정사 모자이크의 밴드 이름(대소문자 무관)으로 찾음. 카메라에 필요한 밴드가 없는 지수(예: Blue가 없는 카메라의 EVI)는
  오류가 아니라 건너뛰고 보고서 `multispectral.indices_skipped`에 남김. 고를 수 있는 지수는 `qo.preview()` 결과의
  `multispectral["index_catalog"]`의 `available`로 미리 확인함
- 분모의 절댓값이 1e-6 이하이거나 입력이 NaN인 화소는 NaN
- 미리보기 범위는 PNG 색칠에만 쓰고, GeoTIFF에는 계산값을 자르지 않고 저장함
- 지수를 만들기 전에 `indices/` 폴더와 0.4.0 형식(`indices.tif`, `ndvi.png`)을 지우므로 선택에서 뺀 지수 파일은 남지 않음.
  SDK는 새 지수를 `indices.new/`에 다 만든 뒤 바꾸므로 도중에 실패·중단하면 이전 지수가 그대로 남음.
  정사 모자이크 재생성에서는 임시 정사 모자이크에서 지수를 만들어 두고 정사 모자이크와 함께 바꿈
- 선택은 `project/meta.json`의 render 설정에 저장되어 `refine()`·`reset_refinement()`의 재생성에 그대로 쓰임 (0.4.1 전에 저장된 설정은 기본값)
- **지수만 다시 만들기**: `Project.make_indices(["NDVI", "NDWI"])` 또는 `quickortho indices <워크스페이스> --indices NDVI,NDWI`.
  정렬·정사투영 없이 반사율 정사 모자이크에서 지수만 계산함 (Bürgewald 5밴드 3451×3659px 기본 3종 약 11초, 9종 약 31초)
- 다른 지수식은 등록하지 않고 `qo.indices.IndexDef`로 만들어 `qo.indices.compute_raster()`에 넘김 ([API](api-reference.md#quickorthoindices-모듈))

### 한계

- DJI Mavic 3M·P4 Multispectral 등 다른 제조사 형식은 아직 지원하지 않음
- 열적외(LWIR) 밴드는 출력하지 않음
- 정렬 결과의 카메라(`Project.cameras()`)·사진 좌표 변환은 기준 밴드 기준임. 사진 이름은 `msref`의 `<원래 이름>.jpg`이지만
  `image_to_ground()`·GCP 표시에는 원래 TIFF 이름도 쓸 수 있음
- 정렬 후 원본 밴드 폴더를 옮기면 정사 모자이크를 다시 만들 수 없음 (`image_dir_missing`). 정렬부터 다시 함

## 11. 수면 처리

바다·호수·저수지는 파도·반사가 영상마다 달라 SfM 점이 생기지 않음. 그래서 간이 DSM이 수면을 주변 육지(방파제, 절벽, 건물)
높이로 외삽하고, 높이가 틀린 만큼 수면이 영상마다 다른 위치에 투영되어 이음매에서 어긋남. 파도 무늬에 생긴 특징점은 영상끼리 맞지
않으면서 영상당 특징점 상한(`max_num_features`)을 차지해 해안선 쪽 특징점을 모자라게 하기도 함.
`OrthoOptions.water`(0.5.0부터)로 이를 처리함. [데스크톱 앱 v0.5.0](https://github.com/SeaViewer91/quick-ortho)과 같은 방식임.

| `water` | 동작 |
|---|---|
| `"auto"` (기본) | 영상 면적 중 수면 비율 평균이 5% 이상이면 켬 |
| `"on"` | 수면이 조금이라도 있으면 처리함 |
| `"off"` | 처리하지 않음 (0.4.x와 같은 결과) |

### 처리 순서

1. **판별** (`water` 단계, 영상당 약 0.15~0.5초): 긴 변 1600px로 읽어 Lab L의 고주파 에너지 |L − G(σ1.5)|를 잼(세밀한 질감).
   480px로 줄인 Lab 색(σ2 블러)과 함께 '매끈하고(에너지 < 0.8), 노란 기가 없고(b* < 3), 청록(a* < −3)이거나 파랑(b* < −5)이며,
   너무 밝지 않은(L < 90)' 곳을 핵심 수면으로 찾음(3×3 열림, 영상의 1% 이상 덩어리).
   핵심 수면에 이어진 덜 엄격한 영역(에너지 < 1.2, b* < 6, L < 90: 해초 띠, 그늘진 물, 탁한 물)까지 넓히고 7×7 닫힘.
   영상의 2% 이상이고 내접원 반지름이 짧은 변의 4% 이상인 덩어리는 '확실한 수면'(2), 나머지 수면은 '후보'(1)로 표시함.
   잔디·그늘진 풀은 세밀한 질감 때문에, 도로는 무채색이라 대부분 빠짐 (480px 질감만 쓰면 잔디 그늘·도로를 수면으로 잡음)
2. **켤지 결정**: `"auto"`는 수면(1, 2) 비율 평균이 5% 이상일 때 켬
3. **특징점 제외** (정렬): 확실한 수면을 짧은 변의 2%만큼 안쪽으로 줄여 COLMAP 마스크로 씀. 물가(갯바위·방파제 발치) 특징점은 남김.
   마스크를 쓰면 모든 영상에 마스크 파일이 있어야 하므로(없으면 COLMAP이 그 영상의 특징점을 뽑지 않음) 수면이 없는 영상은 흰 마스크를 둠.
   확실한 수면이 하나도 없으면 마스크를 쓰지 않음
4. **DSM 수면 평면** (정사, `dsm="sparse"`만): DSM 칸 중심을 DSM 높이로 각 영상에 투영해 수면 표를 모으고,
   본 영상의 절반 이상이 수면이면 후보로 봄. 후보 덩어리(100 m² 이상)마다 다음을 모두 만족해야 수면으로 확정함
   - 안쪽(경계 2 m 제외)의 3D 점 밀도가 육지 평균 밀도의 15% 미만
   - 물가 띠(덩어리를 4 m 넓힌 띠)의 점이 5개 이상. 수면 높이 = 그 점 높이의 25백분위
   - 덩어리 안 점이 max(10, 물가 점 수 × 0.2)개 이상이면, 그 중앙값이 물가 점 중앙값보다 1.5 m 넘게 높지 않음 (청록 지붕 같은 높은 평면 제외)
   - 수면 높이가 물가 점의 5백분위보다 3 m 넘게 높지 않음 (수면은 물가에서 가장 낮은 면)

   확정한 수면 칸만 수면 높이로 덮어씀. **3D 점은 지우지 않음**: 수면 칸의 점을 지우면 물가에 걸친 갯바위 점이 빠져 물가 육지 높이가 나빠짐.
   물가 점이 5개 미만이면(촬영 범위 가장자리 등) 높이 근거가 없으므로 손대지 않음.
   색이 비슷한 평평한 곳(도로, 지붕 안쪽)을 잘못 잡아도 물가 띠가 그 면이라 높이도 그 면의 높이로 잡혀 결과 차이가 작음

### 판별 결과 저장과 재사용

- 판별 결과는 `project/water/<영상 경로>.png`(0/100/200, 하위 폴더 영상은 같은 하위 경로)와 요약 `project/water.json`에 저장됨.
  `orthomosaic()`·`refine()`은 다시 판별하지 않고 이것을 씀. 정렬은 새 판별 결과를 임시 폴더에 만들고 정렬이 끝난 뒤 바꿈
- 정렬을 `water="off"`로 했거나 0.5.0 전 워크스페이스에서 `orthomosaic(OrthoOptions(water="auto"|"on"))`을 부르면 그때 판별해 저장함
  (DSM 수면 평면만 적용됨. 특징점 제외는 정렬 때만 함)
- 수면 처리 방식은 정사 옵션으로 저장되어 `refine()`의 재생성에도 쓰임. 0.5.0 전에 저장된 옵션은 `"off"`
  (그때는 수면 처리 없이 만들었음). `orthomosaic()`은 넘긴 옵션을 씀 (기본 `"auto"`)
- SDK는 판별 결과를 켜지 않을 때도 저장함 (앱은 켰을 때만). 그래서 `auto`로 정렬해 꺼진 워크스페이스도 `on`으로 다시 만들 때 판별을 다시 하지 않음

### 자기 수면 마스크 쓰기

NDWI·딥러닝 분할 결과처럼 더 나은 수면 마스크가 있으면 `Project.set_water_masks()`로 넣음 (영상 이름 → 2차원 배열, 0이 아니면 수면,
사진과 해상도가 달라도 됨). 정렬 전에 넣으면 특징점 제외에도, 정렬 뒤에 넣으면 다음 정사 단계의 DSM 수면 평면에 쓰임.
넣은 마스크는 다시 정렬해도 지우지 않음(`set_water_masks(None)`으로 지움). 확정 조건(점 밀도, 물가 높이)은 넣은 마스크에도 똑같이 적용함.

```python
p = qo.Project.create("flight/", "out/")
p.set_water_masks({"DJI_0001.JPG": ndwi_mask_1 > 0, "DJI_0002.JPG": ndwi_mask_2 > 0})
r = p.process(qo.OrthoOptions(water="on"))
print(r.water.source, r.water.area_m2, r.water.levels_m)   # user, 15458.1, [15.22]
```

판별만 따로(`qo.water.detect`, `classify`), 이미 만든 DSM에 수면 평면만 따로(`qo.water.flatten_dsm`) 쓸 수도 있음 ([API](api-reference.md#quickorthowater-모듈)).

### 측정

- Mavic 2 Pro 해안 마을 13장(고도 150 m): 수면 비율 13%, 1.55 ha를 평면(높이 15.22 m)으로 덮음, 13/13 정합. 데스크톱 앱 v0.5.0과 같은 면적.
  앱에서 잰 영상 간 일관성(연직 영상 2장의 5×5 NCC 중앙값): 수면 0.780 → 0.833, 물가 10 m 띠 0.829 → 0.833, 육지는 그대로.
  수면 높이 추정값이 높이를 바꿔 가며 잰 일관성 최대점과 일치함
- 합성 바다 장면(시험): 수면 DSM 오차 중앙값 0.27 m → 0.02 m, 육지는 그대로
- 수면이 없는 도심 공원 18장은 `auto`면 꺼짐(1.7%). Aukerman 77장을 `on`으로 처리하면 연못 448 m²를 평면으로 처리, 77/77 정합 (앱 측정)

### 한계

- 화면 대부분이 수면인 영상은 여전히 정합되지 않을 수 있음 (특징점이 모자람)
- 파도·반사광이 심한 수면, 탁한 물, 하늘이 비친 수면은 판별하지 못할 수 있음. 해당 데이터로는 아직 검증하지 않았음
- 다중분광에는 적용하지 않음 (`water="on"`이면 경고). 외부·평면 DSM에는 수면 평면을 적용하지 않음
- 정렬에서 특징점을 뺀 영역은 그대로이므로, 수면이 아닌 곳(청록 지붕 안쪽)을 확실한 수면으로 잘못 잡으면 그 안의 특징점을 잃음
