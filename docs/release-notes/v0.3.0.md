# QuickOrtho SDK v0.3.0

> 릴리스: 2026-10-07

정사 모자이크의 화질을 높인 릴리스임. [데스크톱 앱 v0.3.0](https://github.com/SeaViewer91/quick-ortho)과 같은 정사투영 방식임.
결과를 원본 해상도로 만들고, 영상을 평균하지 않고 한 장씩 골라 붙이는 심라인 합성으로 바꿔 상이 여러 개 겹쳐 보이던 문제를 없앰.
**동작 기본값이 바뀌므로** 아래 "호환성"을 확인함.

## 설치

```bash
pip install https://github.com/SeaViewer91/quickortho-sdk/releases/download/v0.3.0/quickortho_sdk-0.3.0-py3-none-any.whl
```

## 개선

- **상 겹침(고스팅) 제거**: 지금까지는 한 지점을 덮는 영상 여러 장을 가중 평균했음. 간이 DSM의 높이가 실제와 다르면
  (수면, 갈대, 부표·통 같은 작은 물체) 영상마다 투영 위치가 조금씩 달라 물체가 여러 개로 흐리게 겹쳐 보였음.
  이제 화소마다 영상 중심에 가장 가까운 영상 하나를 골라 쓰고, 영상이 바뀌는 경계의 몇 화소만 섞어 이음매를 감춤 (심라인 합성).
  화소마다 같은 규칙으로 정하므로 타일 크기·`grid_origin`이 달라도 이음매가 어긋나지 않음. 원리는 [핵심 개념](../concepts.md#8-정사-모자이크-합성-심라인) 참고
- **원본 해상도 출력**: `OrthoOptions.gsd_scale`(명령줄 `--gsd-scale`) 기본값을 2에서 1로 바꿈
- **간이 DSM 개선** (`dsm="sparse"`만 해당): 격자를 평균 점 간격의 1.5배에서 0.5배(최소 0.5m)로 촘촘히 하고,
  평활화를 중앙값 5×5·가우시안 σ 1.0에서 중앙값 3×3·가우시안 σ 0.5로 줄임. 가장 연직인 두 영상 간 5×5 패치 NCC(정합 일관성)가
  Mavic 2 13장에서 0.775 → 0.843, 바다가 많은 세트에서 0.220 → 0.238로 높아짐. `plane`·외부 DSM은 바뀌지 않음
- **영상 캐시 자동 크기**: `OrthoOptions.cache_budget_mb` 기본값을 600에서 `None`(사용 가능한 메모리의 30%, 600~3072MB)으로 바꿈.
  타일을 4×4 묶음 순서로 처리해 같은 영상을 연달아 씀
- `report.json`의 `ortho.blend`: 합성 방식 (`"seamline"`)

## 호환성

- **결과가 커지고 느려짐**: 원본 해상도라 정사 모자이크 단계가 0.2.x보다 2~3배 걸리고 결과 파일이 약 4배 커짐
  - Mavic 2 13장 정사 모자이크 단계: 16초 → 38초, 피크 약 1.1GB
  - Aukerman 77장(18MP): 정사투영 73초 → 187초, COG 변환·미리보기 13초 → 54초, 결과 16510×13758px(2.8cm) 약 318MB, 피크 약 2.6GB
  - (리눅스 VM 2코어 7GB, 데스크톱 앱 v0.3.0 엔진으로 측정. 같은 정사투영 코드임)
- 영상이 수백 장이면 결과가 수 GB가 될 수 있음. 작업 중 중간 파일이 함께 생기므로 결과 예상 크기의 2배 이상 디스크 여유를 확보함
- 이전 해상도로 만들려면 `OrthoOptions(gsd_scale=2)`, 명령줄은 `--gsd-scale 2`를 지정함
- 심라인 합성은 영상이 바뀌는 경계에서 높이가 불확실한 물체(수면, 갈대, 고층 건물 지붕선)가 약간 끊겨 보일 수 있음.
  겹쳐 흐려지는 것보다 판독에 유리함
- **0.2.x 워크스페이스를 `refine()`할 때**: 저장된 정사 옵션을 재사용하는데, 0.2.x가 저장한 값에는 당시 기본값이 그대로 들어 있어
  사용자가 고른 값과 구분되지 않음. 그래서 `gsd_m` 없이 `gsd_scale`이 2(이전 기본값)면 1로, `cache_budget_mb`가 600(이전 기본값)이면
  자동으로 바꿔 쓰고, 바꾼 내용을 그 보고서의 경고로 남기고 워크스페이스에 저장함. 다른 값을 고른 경우와 `gsd_m`을 지정한 경우는 그대로 씀.
  0.2.x에서 일부러 `gsd_scale=2`를 고른 경우도 1로 바뀌므로, 그대로 두려면 보정 후 `bounds`·`dsm` 등 다른 옵션은 그대로 주고
  `gsd_scale=2`로 `orthomosaic()`을 다시 실행함. 데스크톱 앱 v0.2.x의 결과 폴더도 같은 규칙을 따름
  (앱 v0.2.x는 `gsd_m`·`gsd_scale`만 저장하므로 배율 2는 1로, 직접 지정한 GSD는 그대로)
  - 판단 근거: 데스크톱 앱 v0.3.0은 0.3.0 미만 프로젝트를 모두 1배로 다시 만듦. SDK는 사용자가 배율을 직접 지정하는 경우가 많으므로
    이전 기본값과 같은 값만 바꿈. 정렬한 버전과 정사 옵션을 저장한 버전이 다를 수 있어 `project/meta.json`에
    `render_engine_version`(정사 옵션을 저장한 SDK 버전)을 새로 기록하고, 없으면 정렬한 버전으로 판단함
- 내부 함수 `render_orthomosaic()`의 `weight_power` 인자가 없어지고 `feather_px`(기본 6), `block`(기본 4)이 생김 (공개 API 아님)
- `report_version`(1), serve 프로토콜(1), `edits.json` 버전은 그대로
