# QuickOrtho SDK v0.4.0

> 릴리스: 2026-10-11

다중분광 카메라(MicaSense RedEdge·Altum 계열)를 지원하는 릴리스임. 밴드 TIFF 폴더를 RGB 폴더와 같은 함수로 처리해
밴드별 **반사율** 정사 모자이크와 식생지수(NDVI·NDRE·GNDVI)를 만듦.
[데스크톱 앱 v0.4.0](https://github.com/SeaViewer91/quick-ortho)과 같은 처리 방식임.

## 설치

```bash
pip install https://github.com/SeaViewer91/quickortho-sdk/releases/download/v0.4.0/quickortho_sdk-0.4.0-py3-none-any.whl
```

## 새 기능

- **다중분광 정사 모자이크**: RedEdge-MX, RedEdge-MX Dual, RedEdge-P, Altum, Altum-PT의 밴드 TIFF 폴더를 그대로 처리함.
  폴더에 Pix4D 카메라 XMP가 있는 TIFF가 있으면 자동으로 다중분광 경로를 탐 ([핵심 개념 10절](../concepts.md#10-다중분광-처리))
  - 기준 밴드(팬크로매틱, 없으면 Green)를 8비트로 바꿔 SfM을 하고, 메타데이터 내부표정을 고정함
  - 제조사 공개 보정식으로 방사휘도를 구하고, 입사광 센서(DLS)와 패널 촬영으로 반사율을 구함
  - 밴드마다 자기 카메라(기준 밴드 자세 ∘ rig 회전)로 DSM에 투영하고, rig 회전을 비행 영상으로 미세 조정함 (잔차 0.1화소 수준)
  - 캡처 간 반사율 블록 조정으로 구름·DLS 기울기에 의한 캡처 경계 단차를 줄임 (전체 반사율 수준은 유지)
- **산출물**: `orthomosaic.tif`(float32 반사율, nodata NaN, 밴드 설명에 이름), `indices.tif`, `preview.png`(반사율 컬러),
  `ndvi.png`, 보고서 `multispectral` 항목 ([결과물과 보고서](../report.md#multispectral-항목-다중분광))
- **옵션**: `OrthoOptions.radiometry`(`"auto"`, `"dls+panel"`, `"dls"`, `"panel"`, `"radiance"`), `OrthoOptions.ms_normalize`.
  명령줄 `--radiometry`, `--no-ms-normalize`
- **결과 객체**: `OrthoResult.multispectral`(`MultispectralInfo`: 밴드, 파장, 반사율 방식, 지수 경로, 정합 잔차, 캡처 간 불일치),
  `ScanResult.multispectral`(스캔 요약)
- **읽기 함수**: `qo.read_indices(target, index=None)`, `qo.band_names(target)`.
  `read_orthomosaic()`은 다중분광 결과를 `(H, W, 밴드)` float32로 돌려줌
- **`quickortho.multispectral` 모듈**: 정사 모자이크 없이 방사보정만 쓸 때 (`scan`, `MsDataset`, `radiance`, `reflectance_factors`,
  `panel_stats` 등). 새로 공개한 모듈이라 1.0 전까지 바뀔 수 있음
- 진행 단계 `bands`("다중분광 밴드 정합·캡처 간 반사율 보정")
- 정밀 보정(`refine()`)·보정 취소·`orthomosaic()` 재생성 모두 다중분광을 지원함. 보정 시 내부표정을 고정함.
  GCP·타이포인트 표시와 `image_to_ground()`에 기준 밴드 TIFF 이름(`IMG_0001_1.tif`)과 8비트 변환본 이름(`IMG_0001_1.tif.jpg`)을 모두 쓸 수 있음
- 패널 촬영이 있지만 일부 밴드에 패널 정보가 없으면(카메라가 그 밴드에서 패널을 못 찾음) `auto`는 패널 보정 없이 DLS만 쓰고 경고함.
  MicaSense Altum 공개 예제가 이 경우임 (Green 밴드)
- 명시한 `radiometry`에 필요한 DLS·패널 촬영이 없으면 SfM 전에 `invalid_argument`로 알림
- 다시 정렬할 때 기준 밴드 영상을 임시 폴더에 만들고 정렬이 끝난 뒤 바꿈 (새 정렬이 중단·실패해도 이전 결과 유지).
  기준 밴드 영상은 워크스페이스 기준으로 찾으므로 다중분광 워크스페이스를 옮겨도 동작함

## 검증

- 합성 다중분광 비행(MicaSense 형식 TIFF, Green·Red·NIR 12캡처 + 패널)으로 SDK 전체 경로를 시험에 넣음:
  스캔 → SfM → 밴드 정합 → 반사율 → 정사 → 지수 → 보정 → 중단·옵션·명령줄. 반사율 참값 대비 중앙값 비 오차 2% 이내
- 공개 데이터 OpenDroneMap Bürgewald(RedEdge-P 24캡처, CC0): 정렬 24/24, 재투영 0.67px, 밴드 정합 잔차 0.11화소 이하,
  캡처 간 불일치 DLS 9~14% → 6~9%, 191초·피크 1.3GB (2코어 VM)
- MicaSense 공개 예제(RedEdge-MX·RedEdge-MX Dual·RedEdge-P·Altum·Altum-PT)로 메타데이터 해석과 패널 반사율 계산을 확인함
- RGB 경로: 같은 정렬 결과로 0.3.1과 0.4.0이 만든 정사 모자이크·DSM이 화소 단위로 같음을 확인함
- 실제 업무 데이터로는 아직 검증하지 않았음

## 호환성

- RGB 처리 결과는 바뀌지 않음
- 스캔: 다중분광 폴더의 기준 밴드 카메라를 `excluded_cameras`·`cameras[...].selected=False`로 표시하던 문제를 앱 구현과 달리 고침
  (패널 캡처가 먼저 정렬되는 실제 MicaSense 폴더에서 생김)
- `read_orthomosaic()`, `Project.read_orthomosaic()`, `OrthoResult.read()`의 `order` 기본값을 `"RGBA"`에서 `None`으로 바꿈.
  RGB 결과는 `None`이면 RGBA로 읽으므로 동작이 같음. 다중분광 결과에 `order`를 주면 `InputError`(`invalid_argument`)
- `read_raster()`의 `bounds` 밖 채움 값이 파일의 nodata(없으면 0)로 바뀜. RGB 정사 모자이크·DSM은 nodata가 없어 0 그대로임
- 0.3.1 이하가 저장한 정사 옵션에는 `radiometry`·`ms_normalize`가 없으므로 기본값을 씀. 0.3.0의 옵션 이전 규칙은 그대로임
- `OrthoOptions`의 새 필드는 맨 뒤에 추가함. `ScanResult`·`OrthoResult`의 새 필드도 기본값 `None`으로 맨 뒤에 추가함
- 다중분광 워크스페이스의 `project/meta.json`에 `multispectral.source_dir`(원본 밴드 폴더)가 추가되고, `image_dir`는
  `project/msref`(기준 밴드 8비트 영상)를 가리킴. `Project.images`는 원본 밴드 폴더를 돌려줌
- `finalize_cog`가 float 래스터에 예측자 3을 씀 (내부 함수)
- `report_version`(1), serve 프로토콜(1), `edits.json` 버전은 그대로

## 알려진 한계

- DJI Mavic 3M·P4 Multispectral 등 다른 제조사 형식은 아직 지원하지 않음
- 열적외(LWIR) 밴드는 출력하지 않음
- 패널 촬영이 일부 밴드에만 기록된 경우 패널 보정을 쓰지 않음 (위 경고). 밴드별로 부분 적용하는 방식은 앱과 함께 검토 예정
- 정렬 후 원본 밴드 폴더를 옮기면 정사 모자이크를 다시 만들 수 없음 (`image_dir_missing`)
