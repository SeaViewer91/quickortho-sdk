# QuickOrtho SDK v0.5.0

> 릴리스: 2026-10-14

바다·호수가 찍힌 비행을 위한 수면 처리를 추가한 릴리스임. 수면 안쪽의 특징점을 빼고, 간이 DSM의 수면을 물가 높이의 평면으로
덮어 수면에서 생기던 어긋남을 줄임. [데스크톱 앱 v0.5.0](https://github.com/SeaViewer91/quick-ortho)과 같은 판별·확정 기준임.

## 설치

```bash
pip install https://github.com/SeaViewer91/quickortho-sdk/releases/download/v0.5.0/quickortho_sdk-0.5.0-py3-none-any.whl
```

릴리스에 문서 전체를 묶은 HTML(`quickortho-sdk-docs-0.5.0.html`)도 함께 첨부함 (인터넷 없이 열림).

## 새 기능

- **수면 처리** `OrthoOptions.water`: `"auto"`(기본, 영상 면적 중 수면 비율 평균 5% 이상이면 켬), `"on"`, `"off"`(0.4.x와 같은 결과).
  명령줄 `--water auto|on|off` (`ortho`, `align`, `render`). 원리는 [핵심 개념 11절](../concepts.md#11-수면-처리)
  - 판별: 긴 변 1600px의 세밀한 질감(Lab L 고주파 에너지)과 480px Lab 색으로 '매끈하고 푸르거나 청록인' 넓은 영역을 찾고,
    이어진 해초 띠·그늘진 물까지 포함함. 잔디·그늘·도로는 질감·색으로 대부분 빠짐. 진행 단계 `water`("수면 판별")
  - 특징점 제외: 넓고 확실한 수면 안쪽(짧은 변 2% 안으로)의 특징점을 COLMAP 마스크로 뺌 (물가 띠는 남김)
  - DSM 수면 평면: 수면 후보 안에 3D 점이 거의 없고 주변보다 높지 않을 때만 수면으로 확정하고, 물가 띠 점 높이의 25백분위로
    수면 칸을 덮음. 점은 지우지 않음. 희소 점군 DSM(`dsm="sparse"`)에만 적용
  - 판별 결과는 `project/water/`(영상별 PNG)와 `project/water.json`에 저장되어 `orthomosaic()`·`refine()`에서 다시 씀
- **결과**: `OrthoResult.water`, `AlignResult.water` (`WaterInfo`: 방식, 적용 여부, 수면 비율, 특징점 제외 영상 수, 수면 면적, 수면 높이,
  덩어리별 판정). 보고서 `water` 항목 ([결과물과 보고서](../report.md#water-항목-수면-처리))
- **자기 수면 마스크**: `Project.set_water_masks(masks | 폴더 | None)`, `Project.water_masks()`. NDWI·딥러닝 분할 결과 같은 마스크를 넣으면
  SDK 판별 대신 씀 (정렬 전에 넣으면 특징점 제외에도). 확정 조건은 똑같이 적용함
- **`quickortho.water` 모듈**: `classify`, `detect`, `read_masks`, `normalize_masks`, `flatten_dsm`(이미 만든 DSM에 수면 평면만 적용,
  `qo.read_dsm`·`Project.cameras()`·`points()`를 그대로 받음). 새로 공개한 모듈이라 1.0 전까지 바뀔 수 있음
- 명령줄 텍스트 출력에 수면 처리 결과 줄을 추가함
- 릴리스에 문서 HTML 한 파일을 첨부함 (0.4.1 이후 추가)

## SDK 설계 결정

- **판별 결과를 끌 때도 저장**: 앱은 켰을 때만 저장함. SDK는 `auto`로 꺼진 워크스페이스를 `on`으로 다시 만들 때 판별을 다시 하지 않도록
  항상 저장하고, 켤지는 정사 단계마다 그 단계의 `water`로 다시 정함
- **정사 단계에서도 판별**: 정렬을 `off`로 했거나 0.5.0 전 워크스페이스에서 `orthomosaic(water="auto"|"on")`을 부르면 그때 판별해
  DSM 수면 평면을 적용함 (특징점 제외는 정렬 때만 하므로 다시 정렬해야 함)
- **교체 방식**: 정렬은 새 판별 결과를 `water.new`에 만들고 정렬이 끝난 뒤 바꿈. 저장은 임시 폴더에 다 쓴 뒤 바꾸고 이전 폴더를 먼저 옮기므로,
  도중에 실패하거나 Windows에서 파일이 잠겨 있으면 이전 결과가 그대로 남음. 판별 결과를 바꾸지 못해도 정렬 결과는 살리고 경고만 남김
- **사용자 마스크 입력 경로**: 작업 지시의 권장에 따라 둠. 다시 정렬해도 지우지 않고(`None`으로 지움), 이름은 영상 폴더 기준 상대 경로만 받음
  (워크스페이스 밖에 쓰지 않게). 정렬하는 영상과 이름이 맞지 않으면 자동 판별로 돌아감
- **읽지 못한 영상**: 판별에서 잘린 JPEG 등은 육지로 보고 계속함 (앱은 처리 전체가 실패함). SfM도 그 영상을 건너뜀
- **외부·평면 DSM에는 적용하지 않음**: 판별도 하지 않고 보고서에 이유(`note`)를 남김 (앱에는 외부·평면 DSM이 없음)
- **보고서 키 추가**: 앱과 같은 키에 `source`, `levels_m`(모든 수면 덩어리 높이. `detail`은 10개까지), `note`를 더함. 같은 경고는 한 번만 남김
- 다중분광에서 `water="on"`이면 정렬·정사 모두 경고함 (보고서에는 한 번)
- 앱의 '면적 가중 중앙값' 대체 높이 분기는 실행되지 않는 코드라 뺐음 (물가 점이 5개 미만이면 수면으로 확정하지 않으므로)
- 내부 SfM 함수의 마스크 폴더는 공개 `SfmOptions`가 아니라 내부 인자로 둠 (COLMAP 경로 규칙을 버전 간 약속으로 두지 않음)

## 검증

- 앱 시험 7개를 옮김: 잔잔한 수면은 찾고 풀·그늘·작은 지붕은 제외, 질감 있는 파랑 제외, 방식·자동 판정,
  특징점 마스크(물가 띠 유지, 모든 영상에 파일, 확실한 수면이 없으면 안 씀), 마스크 저장(한글·하위 폴더), 바다 평면과 높은 청록 지붕 유지,
  버전별 정사 설정
- SDK 시험 추가: 합성 바다 장면 전체 경로(판별 → 특징점 제외 → SfM → 수면 평면, 수면 DSM 오차 중앙값 0.27 m → 0.02 m, 육지 그대로),
  off 결과, refine 재사용·0.5.0 전 설정 off, 정사 단계 판별, 사용자 마스크(넣기·폴더·재정렬 유지·지우기·잘못된 이름), 공개 함수,
  마스크 형식 판정, 저장 중 실패 시 이전 결과 유지, 옵션 검사·명령줄, 다중분광 경고. `pytest -W error::RuntimeWarning` 전체 통과
- Mavic 2 Pro 해안 마을 13장(데스크톱 앱 측정 데이터): 수면 비율 13%로 켜짐, 특징점 제외 7장, 13/13 정합, 수면 1.55 ha를 높이 15.22 m 평면으로
  덮음. 앱 v0.5.0과 같은 면적
- `water`를 끈 결과와 수면이 없는 장면의 `auto` 결과: 같은 정렬 결과로 0.4.1과 정사 모자이크·DSM·미리보기가 바이트 단위로 같음

## 호환성

- 기본값 `water="auto"`로 RGB 비행에 판별 단계가 추가됨 (영상당 0.15~0.5초). 수면이 5% 미만이면 결과는 0.4.x와 같음.
  진행 이벤트에 `water` 단계가 새로 나옴 (`scan` 다음). `qo.STAGES`에 추가함. 단계 목록을 고정해 진행률을 계산하는 코드는 `water`를 더해야 함
- 0.5.0 전에 저장한 정사 옵션에는 `water`가 없으므로 `refine()`의 재생성에서는 끔 (예전과 같은 결과). `orthomosaic()`은 넘긴 옵션을 씀
- `report.json`에 `water` 항목이 추가됨. `timings_s`에 `water_s`가 추가될 수 있음
- `OrthoOptions`의 새 필드는 맨 뒤에 추가함. `report_version`(1), serve 프로토콜(1), `edits.json` 버전은 그대로
- 다중분광 처리 결과는 바뀌지 않음

## 알려진 한계

- 화면 대부분이 수면인 영상은 여전히 정합되지 않을 수 있음
- 파도·반사광이 심한 수면, 탁한 물, 하늘이 비친 수면은 판별하지 못할 수 있음. 해당 데이터로는 아직 검증하지 않았음 (자기 마스크로 보완 가능)
- 다중분광에는 적용하지 않음
