# QuickOrtho SDK v0.4.1

> 릴리스: 2026-10-11

다중분광 결과에서 만들 식생·수분 지수를 사용자가 고르게 한 릴리스임. 지수를 9종으로 늘리고, 정사 모자이크를 다시 만들지 않고
지수만 다시 만드는 기능을 추가함. [데스크톱 앱 v0.4.1](https://github.com/SeaViewer91/quick-ortho)과 같은 지수·파일 형식임.

## 설치

```bash
pip install https://github.com/SeaViewer91/quickortho-sdk/releases/download/v0.4.1/quickortho_sdk-0.4.1-py3-none-any.whl
```

## 새 기능

- **지수 선택**: `OrthoOptions.indices`(명령줄 `--indices ndvi,ndre`, `none`이면 만들지 않음)로 만들 지수를 고름.
  기본값 `None`은 NDVI·NDRE·GNDVI로 0.4.0과 같은 결과임. 이름은 대소문자를 가리지 않고 중복·순서를 정리함.
  모르는 이름은 정렬·정사투영을 시작하기 전에 `InputError`(`invalid_argument`)
- **지수 추가**: NDWI(수면, McFeeters), OSAVI·SAVI(토양 보정), EVI, CIre·CIg(엽록소). 모두 9종이며 식·필요한 밴드·미리보기 범위는
  [핵심 개념](../concepts.md#식생수분-지수-orthooptionsindices)의 표 참고
- **계산할 수 없는 지수는 건너뜀**: 카메라에 필요한 밴드가 없는 지수(예: Blue가 없는 카메라의 EVI)는 오류 없이 건너뛰고
  `OrthoResult.indices_skipped`, 보고서 `multispectral.indices_skipped`에 남김
- **지수만 다시 만들기**: `Project.make_indices(["NDVI", "NDWI"])`, 명령줄 `quickortho indices <워크스페이스> --indices NDVI,NDWI`.
  반사율 정사 모자이크에서 지수만 계산하고 보고서와 저장된 선택을 갱신함. Bürgewald(5밴드 3451×3659px) 기본 3종 11초, 9종 31초
- **선택 저장**: 고른 지수는 워크스페이스(`meta.json`의 `render.indices`)에 저장되어 `refine()`·`reset_refinement()`의 재생성에 그대로 쓰임
- **지수별 파일**: `indices/<이름>.tif`(float32 단일 밴드 COG, nodata NaN)와 `indices/<이름>.png`(색 띠 미리보기, 긴 변 2048px 이하).
  고르지 않은 지수의 이전 파일과 0.4.0 형식(`indices.tif`, `ndvi.png`)은 지움
- **보고서**: `multispectral.index_legend`(지수별 미리보기 색 범위와 색 띠 3색), `multispectral.indices_skipped`,
  `outputs.indices`·`outputs.index_previews`(`{지수: 경로}`), `make_indices()` 후 `timings_s.indices_s`
- **폴더 미리보기**: `PreviewResult.multispectral`(`preview.json`의 `multispectral`)에 스캔 요약과 `index_catalog`
  (지수마다 `name`, `label`, `bands`, `available`, `default`). 이 카메라로 만들 수 있는 지수를 처리 전에 알 수 있음
- **`quickortho.indices` 모듈**: `INDEX_DEFS`, `DEFAULT_INDICES`, `IndexDef`, `names()`, `normalize()`, `available()`, `catalog()`,
  `legend()`, `compute()`(밴드 배열로 계산), `compute_raster()`(반사율 GeoTIFF·워크스페이스에서 필요한 밴드만 읽어 계산)
  ([API](../api-reference.md#quickorthoindices-모듈)). 새로 공개한 모듈이라 1.0 전까지 바뀔 수 있음

## SDK 설계 결정

- **사용자 지수 등록 함수는 두지 않음**: 고른 지수 이름은 워크스페이스에 저장되어 `refine()`·명령줄·다른 프로세스에서 다시 쓰이는데,
  실행 중에만 등록한 지수는 그때 찾을 수 없어 재생성이 실패함. 대신 `IndexDef`를 직접 만들어 `compute()`·`compute_raster()`에 넘김
- **지수 파일을 다 만든 뒤 교체**: 새 지수를 `indices.new/`에 모두 만든 뒤 `indices/`와 바꿈 (앱은 먼저 지우고 만듦).
  지수를 만드는 중에 실패·중단하면 이전 지수·보고서·저장된 선택이 그대로 남음. 마지막 중단 확인 지점은 교체 직전임.
  이전 `indices/`는 먼저 `indices.old/`로 옮기므로, 다른 프로그램이 지수 파일을 열고 있어(Windows) 옮길 수 없으면 아무것도 바꾸지 않고 오류를 냄.
  결과 파일 구성은 앱과 같음
- **정사 모자이크 재생성에서는 교체 전에 지수를 만듦**: 임시 정사 모자이크에서 지수를 `indices.new/`에 만든 뒤 정사 모자이크·DSM·지수를
  함께 바꿈. 지수 계산이 실패해도 정사 모자이크·지수·보고서 모두 이전 것이 남음
- **저장된 선택 검사**: `refine()`·`reset_refinement()`가 쓰는 저장된 선택이 잘못되었으면(모르는 이름, 문자열 등) 번들 조정·정사투영 끝에
  실패하지 않도록 처음에 검사하고, 기본값으로 만들며 보고서에 경고를 남김. 고친 값은 저장함
- **새 오류 코드** `ProjectError("not_multispectral")`: RGB 결과에 `make_indices()`를 부른 경우 (앱은 일반 오류)
- **`index_catalog`와 `indices` 두 키**: 미리보기의 지수 목록을 작업 지시의 `index_catalog`와 앱 v0.4.1 화면이 읽는 `indices`
  두 키에 같은 값으로 둠 (앱이 SDK로 바뀌어도 화면이 그대로 동작하게)
- `OrthoOptions.indices`에 문자열 하나(`"NDVI"`)를 주면 글자 단위로 쪼개지지 않게 `invalid_argument`로 거부함
- 명령줄 인자 형식은 앱 Rust 호출(`["--indices", "NDVI,NDRE" | "none"]`)과 같음

## 검증

- 앱에서 추가된 시험을 옮김: 고른 지수만 생성·이전 파일(선택 해제 지수, 0.4.0 형식) 삭제, 계산 불가 지수 건너뜀,
  `normalize_selection`(대소문자·중복·순서·잘못된 이름), `index_catalog`의 `available`, 반사율 컬러 미리보기
- SDK 시험 추가: 9종 식의 값, 실패·중단·교체 실패 시 이전 지수 유지(`make_indices` 중단 시 보고서·meta도 그대로,
  정사 재생성 중 지수 실패 시 정사 모자이크도 그대로), 공개 모듈, 잘못 저장된 선택의 기본값 대체, 명령줄 텍스트 출력, 선택 저장과 `refine()` 재사용, 0.4.1 전 설정의 기본값,
  `make_indices()`(정사 모자이크 불변·보고서·meta 갱신·오류 코드), 미리보기 카탈로그, 명령줄 `indices`·`--indices`
- `pytest -W error::RuntimeWarning` 전체 통과
- Bürgewald 0.4.0 워크스페이스에 `make_indices()`(기본 선택): NDVI·NDRE·GNDVI 값과 NaN 위치가 0.4.0 `indices.tif`와 완전히 같음.
  0.4.0 형식 파일은 지워짐
- RGB 경로: 같은 정렬 결과로 0.4.0과 0.4.1이 만든 정사 모자이크·DSM·미리보기가 바이트 단위로 같음

## 호환성

- **`MultispectralInfo.indices`의 형식이 `Path | None`에서 `dict[str, Path]`로 바뀜**. 0.4.0처럼 경로 하나로 쓰던 코드는
  `info.indices["NDVI"]` 또는 `qo.read_indices(workspace)`로 바꿔야 함. `index_names`, `index_preview`, `read_indices()`는 그대로 씀
- 보고서 `outputs.indices`가 다중밴드 파일 경로 문자열에서 `{지수: 경로}`로 바뀌고 `outputs.index_preview`가 `outputs.index_previews`로 바뀜
- 0.4.0 결과 폴더는 그대로 열고 읽을 수 있음 (`read_indices()`, `index_names`, `index_preview`가 이전 형식을 읽음).
  정사 모자이크·지수를 다시 만들면 새 형식으로 바뀌고 `indices.tif`·`ndvi.png`는 지워짐
- 0.4.0 이하가 저장한 정사 옵션에는 `indices`가 없으므로 `refine()`의 재생성에서 기본값(NDVI·NDRE·GNDVI)을 씀
- `orthomosaic()`은 저장값이 아니라 넘긴 `OrthoOptions.indices`를 씀 (다른 옵션과 같음)
- RGB 영상에는 `indices`를 쓰지 않음 (RGB 처리 결과는 바뀌지 않음)
- `OrthoOptions`·`PreviewResult`의 새 필드는 기본값 `None`으로 맨 뒤에 추가함
- `report_version`(1), serve 프로토콜(1), `edits.json` 버전은 그대로

## 알려진 한계

- 0.4.0의 한계(다른 제조사 형식, 열적외, 일부 밴드에만 기록된 패널)는 그대로임
