# QuickOrtho SDK v0.2.1

> 릴리스: 2026-10-02

Windows 현장 노트북에서 발견한 오류 두 건을 고친 수정 릴리스임. 공개 API 변경은 없음.

## 설치

```bash
pip install https://github.com/SeaViewer91/quickortho-sdk/releases/download/v0.2.1/quickortho_sdk-0.2.1-py3-none-any.whl
```

## 고친 문제

- **PostGIS·QGIS가 설치된 Windows에서 정사 모자이크 실패**: `The EPSG code is unknown ... It comes from another PROJ installation`.
  시스템 환경변수 `PROJ_LIB` 등이 다른 버전의 PROJ 데이터를 가리켜 rasterio가 읽지 못한 것이 원인임.
  `import quickortho` 시점에 rasterio에 들어 있는 데이터 폴더로 바꾸고 `GDAL_DRIVER_PATH`를 지움 (프로세스 안에서만).
  pyproj는 원래 자기 데이터를 먼저 써서 영향이 없었으므로, 기존 `doctor`의 좌표 변환 항목은 이 문제를 잡지 못했음
- **처리 중 `database is locked`로 프로세스 종료**: 진행률을 읽는 연결이 COLMAP의 DB 쓰기와 겹치면 COLMAP이 프로세스를 종료함
  (COLMAP은 잠금 대기 시간을 두지 않음). 잠금을 전혀 잡지 않는 `immutable=1` 연결로 바꿈. 진행률을 0.05초마다 읽는 시험에서
  이전 방식은 4회 중 4회 종료, 새 방식은 5회 모두 정상
- **데스크톱 앱 v0.2.0이 정렬 직후 실패한 워크스페이스**: 보고서 파일이 하나도 없어 `orthomosaic()`/`render`의 보고서에 정합 정보가
  빠지던 문제. 재구성에서 정합 수·재투영 오차·GPS 잔차를 다시 계산해 정렬 보고서를 만듦

## 진단

- `quickortho version`: 바꾼 환경변수와 원래 값(`geo_env_overridden`)
- `quickortho doctor`: "좌표계 (GeoTIFF 저장)" 항목 추가 (rasterio로 EPSG:5186을 읽어 봄)
