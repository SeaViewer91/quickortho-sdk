# QuickOrtho SDK v0.3.1

> 릴리스: 2026-10-08

0.3.0의 심라인 합성에서 영상 경계마다 보이던 밝기 단차를 없앤 릴리스임.
[데스크톱 앱 v0.3.1](https://github.com/SeaViewer91/quick-ortho)과 같은 보정 방식임.

## 설치

```bash
pip install https://github.com/SeaViewer91/quickortho-sdk/releases/download/v0.3.1/quickortho_sdk-0.3.1-py3-none-any.whl
```

## 개선

- **영상 경계의 밝기 단차 제거**: 0.3.0부터 화소마다 영상 하나를 골라 붙이면서, 영상끼리 노출이나 태양 방향에 따른
  지면 반사(모래사장, 잔디밭)가 다르면 경계를 따라 계단·다각형 모양의 밝기 차가 뚜렷하게 보였음.
  정사투영 전에 `color` 단계("영상 간 밝기·색 보정")를 추가해 영상마다 완만한 밝기 보정 곡면(영상 좌표의 2차 다항식)을 구해
  읽은 색에 곱함. 넓은 범위의 밝기 차이만 맞추고 세부 질감은 원래 영상 그대로 쓰므로 선명도는 유지됨.
  원리는 [핵심 개념](../concepts.md#밝기색-보정) 참고
- 건물 옆면, 파도처럼 영상마다 보이는 내용이 다른 곳은 반복 재가중으로 보정 계산에서 빠져 색 얼룩이 생기지 않음
- 정밀 보정(`refine()`)에서 다시 만드는 정사 모자이크에도 적용됨. 외부·평면 DSM에서도 동작함
- 이득은 결과 범위(`bounds`)가 아니라 촬영 범위 전체로 구함. 범위·격자 기준점을 바꿔 나눠 만든 결과끼리도 같은 이득을 써서
  이어 붙여도 밝기가 어긋나지 않음. 그래서 좁은 `bounds`를 줘도 이 단계는 영상 전체를 읽음
- 새 옵션 `OrthoOptions.color_balance`(기본 `True`), 명령줄 `--no-color-balance`
- `report.json`: `ortho.color_balance`, `ortho.color`(보정 격자·이득 분포), `timings_s.color_s`

## 처리 시간

`color` 단계는 정사 모자이크 단계의 약 3~10%임. Mavic 2 13장 2.9초, 18장 3.1초, Aukerman 77장 14초
(리눅스 VM 2코어, 데스크톱 앱 v0.3.1 엔진으로 측정. 같은 보정 코드임). 피크 메모리 변화는 거의 없음.

## 호환성

- 진행 이벤트에 단계 `color`가 새로 나옴 (`dsm`과 `ortho` 사이). `qo.STAGES`에 추가함.
  단계 목록을 고정해 두고 전체 진행률을 계산하는 코드는 `color`를 더해야 함 ([진행률과 중단](../events-and-cancel.md#단계-순서))
- 0.3.0 이하가 저장한 정사 옵션에는 `color_balance`가 없으므로 `refine()`의 재생성에서 기본값(켬)을 씀
- 0.3.0의 옵션 이전 규칙(0.3.0 미만이 저장한 `gsd_scale` 2·캐시 600을 새 기본값으로)과 `render_engine_version` 기록은 그대로임
- 결과가 0.3.0과 달라짐 (밝기). 0.3.0과 같게 만들려면 `color_balance=False`
- `OrthoOptions`의 새 필드는 맨 뒤에 추가해 위치 인자로 만든 기존 코드에 영향이 없음
- `report_version`(1), serve 프로토콜(1), `edits.json` 버전은 그대로

## 알려진 한계

- 고층 건물의 지붕선이 영상 경계에서 어긋나 보이는 것은 밝기가 아니라 간이 DSM의 높이 문제라 이번 보정으로 바뀌지 않음

## 기타

앱 구현과 다른 점 (SDK에만 있는 `bounds` 옵션과 진행 이벤트 때문):

- 이득을 결과 범위 대신 촬영 범위 전체로 구함 (위 설명). 앱은 결과 범위가 늘 촬영 범위라 결과가 사실상 같음
- `color` 진행률을 두 번의 통과(영상 수 × 2)로 나눠 올려 첫 통과에도 중단 확인 지점을 둠. 결과 범위 밖 영상이 마지막에 와도 끝까지 올라감
- 이득 맵을 만든 영상이 없으면 보정하지 않은 것으로 보고함 (`ortho.color_balance: false`)
